## 一、构建配置


### 1.1 `pom.xml`

> 依赖、编译配置、exec 插件的参数传递方式。三个编码参数一个都不能少。
>
> **文件路径**：`pom.xml`（工程根目录）

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd">
  <modelVersion>4.0.0</modelVersion>

  <groupId>com.example.mcp</groupId>
  <artifactId>mcp-java-tutorial</artifactId>
  <version>1.0.0</version>
  <packaging>jar</packaging>
  <name>MCP Java Tutorial</name>

  <properties>
    <maven.compiler.release>17</maven.compiler.release>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    <!-- MCP 官方 Java SDK。2.0.0 是当前稳定版，对应 MCP 规范 2025-11-25 -->
    <mcp.sdk.version>2.0.0</mcp.sdk.version>
    <!-- Anthropic 官方 Java SDK -->
    <anthropic.sdk.version>2.34.0</anthropic.sdk.version>

    <!--
      传给被测程序的参数。
      为什么不用标准的 -Dexec.args？因为它会被 exec 插件插到【主类名之前】，
      结果 java 把参数当成了主类名，报 ClassNotFoundException。
      用自定义属性显式放进 <arguments> 里，位置才对。
      用法：-DappArgs="你的问题"
    -->
    <appArgs></appArgs>
  </properties>

  <dependencyManagement>
    <dependencies>
      <!-- BOM：统一管理 mcp / mcp-core / mcp-json-* 等模块的版本 -->
      <dependency>
        <groupId>io.modelcontextprotocol.sdk</groupId>
        <artifactId>mcp-bom</artifactId>
        <version>${mcp.sdk.version}</version>
        <type>pom</type>
        <scope>import</scope>
      </dependency>
    </dependencies>
  </dependencyManagement>

  <dependencies>
    <!-- 便捷包：= mcp-core + Jackson3 JSON 实现，含 STDIO / Streamable HTTP 传输 -->
    <dependency>
      <groupId>io.modelcontextprotocol.sdk</groupId>
      <artifactId>mcp</artifactId>
    </dependency>

    <!-- 调用 Claude 用 -->
    <dependency>
      <groupId>com.anthropic</groupId>
      <artifactId>anthropic-java</artifactId>
      <version>${anthropic.sdk.version}</version>
    </dependency>

    <!--
      H2：内存数据库，纯 Java、零安装。
      用它只是为了让示例自包含——换成你真实的库，
      只需要改 Db.java 里的 JDBC URL 和账号，其他代码一行不用动。
    -->
    <dependency>
      <groupId>com.h2database</groupId>
      <artifactId>h2</artifactId>
      <version>2.3.232</version>
    </dependency>

    <!--
      日志。必须走 stderr！
      STDIO 传输把 stdout 当作 JSON-RPC 通道，任何打到 stdout 的日志
      都会污染协议流，导致客户端解析失败。slf4j-simple 默认输出到 System.err，
      正好安全。这是 MCP 新手最常踩的坑。
    -->
    <dependency>
      <groupId>org.slf4j</groupId>
      <artifactId>slf4j-simple</artifactId>
      <version>2.0.16</version>
    </dependency>
  </dependencies>

  <build>
    <plugins>
      <!--
        用 exec:exec 而不是 exec:java，是这里的关键。
        exec:java 在同进程里跑，System.getProperty("java.class.path") 不可靠；
        exec:exec 是真的 fork 一个 java 进程，classpath 是真的，
        于是 step2 / step4 才能用同一份 classpath 把 server 拉起来当子进程。
      -->
      <plugin>
        <groupId>org.codehaus.mojo</groupId>
        <artifactId>exec-maven-plugin</artifactId>
        <version>3.5.0</version>
        <configuration>
          <executable>java</executable>
          <arguments>
            <!--
              Windows 中文乱码的坑，比看起来深：
              Java 18+ 已经把 file.encoding 默认成 UTF-8，但 System.out 走的是
              stdout.encoding，它在 Windows 上仍然跟随控制台代码页（中文系统是 GBK）。
              结果就是文件读写正常、println 出来的中文全乱。
              必须单独指定 stdout/stderr 编码，缺一不可。
            -->
            <argument>-Dfile.encoding=UTF-8</argument>
            <argument>-Dstdout.encoding=UTF-8</argument>
            <argument>-Dstderr.encoding=UTF-8</argument>
            <argument>-classpath</argument>
            <classpath/>
            <argument>${mainClass}</argument>
            <argument>${appArgs}</argument>
          </arguments>
        </configuration>
      </plugin>
    </plugins>
  </build>
</project>
```

### 1.2 `simplelogger.properties`

> 日志配置。核心是**必须走 stderr** —— stdout 是 MCP 的协议通道，污染了会解析失败。
>
> **文件路径**：`src/main/resources/simplelogger.properties`

```properties
# ---------------------------------------------------------------------------
# 日志配置。
#
# 默认只显示 warn 及以上，避免 SDK 的内部日志淹没示例输出。
# 想观察 MCP 协议细节（initialize 握手、能力协商、server 的 stderr 回显），
# 把下面这行改成 info —— 这是理解 MCP 生命周期最直观的方式：
#
#   org.slf4j.simpleLogger.defaultLogLevel=info
# ---------------------------------------------------------------------------
org.slf4j.simpleLogger.defaultLogLevel=warn

# 关键：必须输出到 stderr，绝不能是 stdout。
# STDIO 传输把 stdout 独占为 JSON-RPC 通道。
org.slf4j.simpleLogger.logFile=System.err

org.slf4j.simpleLogger.showThreadName=true
org.slf4j.simpleLogger.showDateTime=false

# ---------------------------------------------------------------------------
# 关掉一条会误导人的警告。
#
# 现象：每次正常结束后，客户端都会打印
#   WARN StdioClientTransport - MCP server process failed with code 1
#
# 原因：客户端 SDK 在 closeGracefully() 里会强杀 server 子进程，
#       而 Windows 上被强杀的进程退出码固定是 1。
#       也就是说，这行警告出现在【正常关闭】路径上，不是崩溃。
#
# 为什么可以放心降级（都实测验证过）：
#   · 关闭后没有残留 java 进程
#   · server 端做了 stdin EOF 感知（见 StdioLifecycle），
#     客户端异常消失时 server 能自己以退出码 0 退出，不会变孤儿
#
# 如果你在别的地方看到这条警告，且伴随进程残留，那才是真问题。
# ---------------------------------------------------------------------------
org.slf4j.simpleLogger.log.io.modelcontextprotocol.client.transport.StdioClientTransport=error
```

### 2.1 Step1 —— MCP Server

> 一个最小的 MCP Server，暴露 add / get_weather 两个工具。注意这里完全没有 LLM。
>
> **文件路径**：`src/main/java/com/example/mcp/step1/CalculatorServer.java`

```java
package com.example.mcp.step1;

import com.example.mcp.core.StdioLifecycle;

import io.modelcontextprotocol.json.McpJsonMapper;
import io.modelcontextprotocol.json.jackson3.JacksonMcpJsonMapperSupplier;
import io.modelcontextprotocol.server.McpServer;
import io.modelcontextprotocol.server.McpSyncServer;
import io.modelcontextprotocol.spec.McpSchema;

import java.util.List;
import java.util.Map;

/**
 * 【第 1 步】一个最小可用的 MCP Server。
 *
 * 关键认知：这个类里完全没有 LLM。
 * MCP Server 不知道 Claude 的存在，它只是一个"能被标准协议调用的工具集合"。
 * 任何 MCP 客户端（Claude Desktop、IDE、你自己写的程序）都能调它。
 *
 * 运行方式（server 不需要参数，它通过 stdin/stdout 通信）：
 *   mvn -q exec:exec -DmainClass=com.example.mcp.step1.CalculatorServer
 *
 * 但你不会想手动跑它——它是被客户端以子进程方式拉起来的。
 * 想单独验证，见 step2 的 ManualClient。
 */
public final class CalculatorServer {

    public static void main(String[] args) {
        // JSON 序列化实现。SDK 通过 SPI 找到 Jackson3 的实现，
        // 这个 Supplier 就是官方给的默认入口。
        McpJsonMapper jsonMapper = new JacksonMcpJsonMapperSupplier().get();

        // ------------------------------------------------------------------
        // 1) 用 JSON Schema 描述工具的入参
        //
        // 注意：这就是一份普通的 JSON Schema。MCP 没有发明新的 schema 语言，
        // 它直接复用 JSON Schema。这一点很重要——后面接 Claude 时，
        // 这份 schema 几乎可以原样转成 Claude 的 tool.input_schema。
        // ------------------------------------------------------------------
        Map<String, Object> addSchema = Map.of(
                "type", "object",
                "properties", Map.of(
                        "a", Map.of("type", "integer", "description", "第一个加数"),
                        "b", Map.of("type", "integer", "description", "第二个加数")
                ),
                "required", List.of("a", "b")
        );

        Map<String, Object> weatherSchema = Map.of(
                "type", "object",
                "properties", Map.of(
                        "city", Map.of("type", "string", "description", "城市名，例如：北京")
                ),
                "required", List.of("city")
        );

        // ------------------------------------------------------------------
        // 2) 声明工具
        //
        // description 极其重要：模型就是靠它决定"什么时候该调这个工具"。
        // 写清楚"做什么"+"什么时候用"，比写清楚参数更重要。
        // ------------------------------------------------------------------
        McpSchema.Tool addTool = McpSchema.Tool.builder("add", addSchema)
                .description("计算两个整数之和。当用户询问加法运算时使用。")
                .build();

        McpSchema.Tool weatherTool = McpSchema.Tool.builder("get_weather", weatherSchema)
                .description("查询指定城市的当前天气。当用户询问天气时使用。")
                .build();

        // ------------------------------------------------------------------
        // 3) 组装并启动 server
        //
        // StdioServerTransportProvider：用标准输入/输出收发 JSON-RPC 消息。
        // 这也是为什么绝对不能用 System.out.println 打日志——会污染协议流。
        // ------------------------------------------------------------------
        StdioLifecycle.Handle lifecycle = StdioLifecycle.create(jsonMapper);

        McpSyncServer server = McpServer.sync(lifecycle.provider())
                // 名字和版本会在 initialize 握手时告诉客户端
                .serverInfo("calc-server", "1.0.0")
                // 能力协商：我提供 tools。客户端据此知道可以调 tools/list、tools/call
                .capabilities(McpSchema.ServerCapabilities.builder().tools(true).build())

                // toolCall 是注册工具的便捷写法，等价于构造一个 SyncToolSpecification。
                // lambda 的两个参数：
                //   exchange —— 可用于反向请求客户端（比如 sampling，让它帮忙调 LLM）
                //   request  —— 内含 name() 和 arguments()，arguments() 就是模型填的参数
                .toolCall(addTool, (exchange, request) -> {
                    int a = ((Number) request.arguments().get("a")).intValue();
                    int b = ((Number) request.arguments().get("b")).intValue();
                    return McpSchema.CallToolResult.builder()
                            .addTextContent(a + " + " + b + " = " + (a + b))
                            .build();
                })

                .toolCall(weatherTool, (exchange, request) -> {
                    String city = String.valueOf(request.arguments().get("city"));
                    // 假的天气数据，用城市名做确定性哈希，保证每次演示结果一致
                    String[] conditions = {"晴", "多云", "小雨", "阴"};
                    int hash = Math.abs(city.hashCode());
                    String condition = conditions[hash % conditions.length];
                    int temp = 10 + hash % 20;
                    return McpSchema.CallToolResult.builder()
                            .addTextContent(city + "：%s，%d°C".formatted(condition, temp))
                            .build();
                })

                .build();

        // 日志走 stderr。用 System.err 而不是 logger 只是为了让这个例子零配置可跑。
        System.err.println("[calc-server] 已启动，等待 stdin 上的 JSON-RPC 消息...");

        // 阻塞直到客户端断开（stdin EOF），然后干净退出。
        // 不要用 `new CountDownLatch(1).await()` 永久阻塞——
        // 那样客户端崩了之后 server 会变成孤儿进程。
        lifecycle.awaitClientDisconnect();
        try {
            server.closeGracefully();
        } catch (Exception ignored) {
            // 已经关了，正常
        }
    }
}
```

### 2.2 Step2 —— MCP Client（无 LLM）

> 直接调用工具，不接模型。这一步是理解 MCP 的关键：它证明 MCP 是「程序调工具」的协议。
>
> **文件路径**：`src/main/java/com/example/mcp/step2/ManualClient.java`

```java
package com.example.mcp.step2;

import io.modelcontextprotocol.client.McpClient;
import io.modelcontextprotocol.client.McpSyncClient;
import io.modelcontextprotocol.client.transport.ServerParameters;
import io.modelcontextprotocol.client.transport.StdioClientTransport;
import io.modelcontextprotocol.json.McpJsonMapper;
import io.modelcontextprotocol.json.jackson3.JacksonMcpJsonMapperSupplier;
import io.modelcontextprotocol.spec.McpSchema;

import java.time.Duration;
import java.util.Map;

/**
 * 【第 2 步】一个纯 MCP 客户端 —— 注意，这里依然没有 LLM。
 *
 * 这是整个教程里最重要的一步，因为它证明了一件事：
 *   MCP 是"程序调用工具"的协议，不是"模型调用工具"的协议。
 *
 * 第 3、4 步才把 Claude 接进来，让模型来决定调哪个工具。
 * 把这两件事分开理解，你就不会再把 MCP 和 function calling 搞混。
 *
 * 运行：
 *   mvn -q compile exec:exec -DmainClass=com.example.mcp.step2.ManualClient
 */
public final class ManualClient {

    public static void main(String[] args) {
        McpJsonMapper jsonMapper = new JacksonMcpJsonMapperSupplier().get();

        // ------------------------------------------------------------------
        // 1) 描述"怎么启动 server"
        //
        // 这就是 MCP 的核心设计：客户端不关心 server 是 Java、Python 还是 Node 写的，
        // 只关心"用什么命令能把它拉起来，然后用 stdio 说 JSON-RPC"。
        // 一个 Python 写的 server，这里就换成 ("python", "-m", "my_server")。
        // ------------------------------------------------------------------
        ServerParameters serverParams = ServerParameters.builder("java")
                // 关键：复用当前进程的 classpath，子进程才能找到 CalculatorServer。
                // 编码参数同样要带上，否则子进程打的日志会是乱码（见 pom.xml 里的说明）。
                .args("-Dfile.encoding=UTF-8",
                      "-Dstdout.encoding=UTF-8",
                      "-Dstderr.encoding=UTF-8",
                      "-classpath", System.getProperty("java.class.path"),
                      "com.example.mcp.step1.CalculatorServer")
                .build();

        // ------------------------------------------------------------------
        // 2) 建立连接
        //
        // StdioClientTransport 会在第一次通信时真正 fork 出 server 子进程。
        // MCP 有两种主流传输：STDIO（本地子进程）和 Streamable HTTP（远程服务）。
        // 旧的 HTTP+SSE 传输已废弃，新项目别再用。
        // ------------------------------------------------------------------
        McpSyncClient client = McpClient.sync(new StdioClientTransport(serverParams, jsonMapper))
                .requestTimeout(Duration.ofSeconds(30))
                .build();

        try {
            // ------------------------------------------------------------------
            // 3) 握手：initialize
            //
            // 这一步会交换双方的身份和能力：
            //   客户端说：我支持 roots / sampling / elicitation
            //   server 说：我提供 tools / resources / prompts
            // 协商完成后，双方才知道接下来能发什么请求。
            // ------------------------------------------------------------------
            client.initialize();

            McpSchema.Implementation info = client.getServerInfo();
            System.out.println("已连接: " + info.name() + " v" + info.version());
            System.out.println("server 能力: " + client.getServerCapabilities());
            System.out.println();

            // ------------------------------------------------------------------
            // 4) tools/list —— 发现工具有哪些
            //
            // 返回的就是 step1 里声明的 name / description / inputSchema。
            // 在没有 LLM 的世界里，这一步的用途是让调用方（人或程序）知道能干什么。
            // 在第 3 步你会看到，它恰好就是喂给 Claude 的工具清单。
            // ------------------------------------------------------------------
            System.out.println("=== tools/list ===");
            McpSchema.ListToolsResult tools = client.listTools();
            for (McpSchema.Tool tool : tools.tools()) {
                System.out.println("• " + tool.name());
                System.out.println("  描述  : " + tool.description());
                System.out.println("  schema: " + tool.inputSchema());
            }
            System.out.println();

            // ------------------------------------------------------------------
            // 5) tools/call —— 真正调用
            //
            // 注意参数是一个普通 Map。没有魔法，没有模型，
            // 就是我们自己决定要调 add，自己填了 a=3, b=4。
            // ------------------------------------------------------------------
            System.out.println("=== tools/call ===");
            McpSchema.CallToolResult r1 = client.callTool(
                    new McpSchema.CallToolRequest("add", Map.of("a", 3, "b", 4)));
            System.out.println("add(3, 4)          -> " + text(r1));

            McpSchema.CallToolResult r2 = client.callTool(
                    new McpSchema.CallToolRequest("get_weather", Map.of("city", "北京")));
            System.out.println("get_weather(北京)  -> " + text(r2));

            // ------------------------------------------------------------------
            // 6) 服务端校验：故意传错参数类型
            //
            // SDK 默认会按 inputSchema 校验入参，不合法就返回 isError=true，
            // 根本不进 handler。这是一个容易被忽略但很有用的安全网。
            // 想关掉：server 端 .validateToolInputs(false)
            // ------------------------------------------------------------------
            System.out.println();
            System.out.println("=== 故意传错参数（a 传字符串）===");
            McpSchema.CallToolResult bad = client.callTool(
                    new McpSchema.CallToolRequest("add", Map.of("a", "不是数字", "b", 1)));
            System.out.println("isError = " + bad.isError());
            System.out.println("content = " + text(bad));

        } finally {
            // 必须优雅关闭：它会终止 fork 出来的 server 子进程。
            // 漏掉这行最典型的症状是跑完一次后，一堆 java 进程赖着不走。
            client.closeGracefully();
        }
    }

    /** CallToolResult.content() 是 Content 列表，文本在 TextContent 里。 */
    private static String text(McpSchema.CallToolResult result) {
        StringBuilder sb = new StringBuilder();
        for (McpSchema.Content c : result.content()) {
            if (c instanceof McpSchema.TextContent t) {
                sb.append(t.text());
            }
        }
        return sb.toString();
    }
}
```

### 2.3 Step3 —— 桥接层

> 把 MCP 工具转成 Claude 工具。会发现它短得离谱，因为两边用的是同一份 JSON Schema。
>
> **文件路径**：`src/main/java/com/example/mcp/step3/McpToClaudeTool.java`

```java
package com.example.mcp.step3;

import com.anthropic.core.JsonValue;
import com.anthropic.models.messages.Tool;
import io.modelcontextprotocol.spec.McpSchema;

import java.util.List;
import java.util.Map;

/**
 * 【第 3 步】桥接：把 MCP 工具翻译成 Claude 能看懂的工具。
 *
 * 这个类是整个教程里最"解气"的地方——你会发现它短得离谱。
 *
 * 为什么这么短？因为两边用的是同一样东西：JSON Schema。
 *   MCP 的 Tool.inputSchema      -> Map<String, Object>（一份 JSON Schema）
 *   Claude 的 Tool.inputSchema   -> 结构化的 Properties
 * 本质上只是把同一份 schema 从左口袋挪到右口袋。
 *
 * 这也解释了一个常见困惑："MCP 和 function calling 到底什么关系？"
 *   答：function calling 是模型侧的机制（模型输出一个 tool_use 表示想调用），
 *       MCP 是工具侧的机制（工具怎么被发现和调用）。
 *       两者正交，所以需要这样一层薄薄的胶水把它们接起来。
 */
public final class McpToClaudeTool {

    private McpToClaudeTool() {
    }

    @SuppressWarnings("unchecked")
    public static Tool toClaudeTool(McpSchema.Tool mcpTool) {
        Map<String, Object> schema = mcpTool.inputSchema();

        // --- properties ---
        Tool.InputSchema.Properties.Builder propsBuilder = Tool.InputSchema.Properties.builder();
        Object rawProps = schema.get("properties");
        if (rawProps instanceof Map<?, ?> props) {
            props.forEach((key, value) ->
                    propsBuilder.putAdditionalProperty(String.valueOf(key), JsonValue.from(value)));
        }

        Tool.InputSchema.Builder schemaBuilder = Tool.InputSchema.builder()
                .properties(propsBuilder.build());

        // --- required ---
        // 注意：required 为空时不要调用 .required(List.of())，
        // 有些版本会把它序列化成 "required": []，虽然合法但没必要。
        Object rawRequired = schema.get("required");
        if (rawRequired instanceof List<?> required && !required.isEmpty()) {
            schemaBuilder.required(required.stream().map(String::valueOf).toList());
        }

        return Tool.builder()
                .name(mcpTool.name())
                .description(mcpTool.description() == null ? "" : mcpTool.description())
                .inputSchema(schemaBuilder.build())
                .build();
    }
}
```

### 2.4 Step4 —— 完整 agent loop

> 把前三步串起来。所谓 agent，本质就是这个 while 循环。
>
> **文件路径**：`src/main/java/com/example/mcp/step4/AgentMain.java`

```java
package com.example.mcp.step4;

import com.anthropic.client.AnthropicClient;
import com.anthropic.client.okhttp.AnthropicOkHttpClient;
import com.anthropic.models.messages.ContentBlock;
import com.anthropic.models.messages.ContentBlockParam;
import com.anthropic.models.messages.Message;
import com.anthropic.models.messages.MessageCreateParams;
import com.anthropic.models.messages.MessageParam;
import com.anthropic.models.messages.StopReason;
import com.anthropic.models.messages.Tool;
import com.anthropic.models.messages.ToolResultBlockParam;
import com.anthropic.models.messages.ToolUseBlock;

import com.example.mcp.step3.McpToClaudeTool;

import io.modelcontextprotocol.client.McpClient;
import io.modelcontextprotocol.client.McpSyncClient;
import io.modelcontextprotocol.client.transport.ServerParameters;
import io.modelcontextprotocol.client.transport.StdioClientTransport;
import io.modelcontextprotocol.json.McpJsonMapper;
import io.modelcontextprotocol.json.jackson3.JacksonMcpJsonMapperSupplier;
import io.modelcontextprotocol.spec.McpSchema;

import java.time.Duration;
import java.util.ArrayList;
import java.util.List;
import java.util.Map;

/**
 * 【第 4 步】把上面三步串起来 —— 完整的 agent loop。
 *
 * 一次完整的交互长这样：
 *
 *   用户提问
 *      │
 *      ▼
 *   ① 把 MCP 工具清单转成 Claude 的 tools，连同问题一起发给 Claude
 *      │
 *      ▼
 *   ② Claude 返回 stop_reason = "tool_use"，带着它想调的工具和参数
 *      │
 *      ▼
 *   ③ 我们拿着这个参数，通过 MCP client 调 MCP server
 *      │
 *      ▼
 *   ④ 把结果包成 tool_result 塞回对话，再发给 Claude
 *      │
 *      ▼
 *   ⑤ Claude 看到结果，返回 stop_reason = "end_turn" 和最终回答
 *      │
 *      ▼
 *    循环结束
 *
 * 所谓 "agent"，本质就是这个 while 循环。没有更玄的东西。
 *
 * 运行（需要 ANTHROPIC_API_KEY）：
 *   mvn -q compile exec:exec -DmainClass=com.example.mcp.step4.AgentMain
 *
 * 也可以带自定义问题：
 *   mvn -q compile exec:exec -DmainClass=com.example.mcp.step4.AgentMain \
 *       -Dexec.args="北京天气怎么样？另外帮我算 999 乘 111"   # 注意：没有乘法的工具，看它怎么办
 */
public final class AgentMain {

    /** 模型 ID。用当前最强的 Opus。 */
    private static final String MODEL = "claude-opus-5";

    /** 防御性上限：万一模型陷入循环，别让它无限烧 token。 */
    private static final int MAX_TURNS = 10;

    public static void main(String[] args) {
        // pom 里的 ${appArgs} 为空时会传进来一个空字符串，过滤掉
        String[] effective = java.util.Arrays.stream(args)
                .filter(a -> !a.isBlank())
                .toArray(String[]::new);

        String question = effective.length > 0
                ? String.join(" ", effective)
                : "北京天气怎么样？另外帮我算一下 1234 加 5678";

        System.out.println("用户: " + question);
        System.out.println("─".repeat(60));

        // ==================================================================
        // 准备阶段 A：起 MCP client（和 step2 完全一样）
        // ==================================================================
        McpJsonMapper jsonMapper = new JacksonMcpJsonMapperSupplier().get();

        ServerParameters serverParams = ServerParameters.builder("java")
                .args("-Dfile.encoding=UTF-8",
                      "-Dstdout.encoding=UTF-8",
                      "-Dstderr.encoding=UTF-8",
                      "-classpath", System.getProperty("java.class.path"),
                      "com.example.mcp.step1.CalculatorServer")
                .build();

        McpSyncClient mcp = McpClient.sync(new StdioClientTransport(serverParams, jsonMapper))
                .requestTimeout(Duration.ofSeconds(30))
                .build();

        // ==================================================================
        // 准备阶段 B：起 Claude client
        // 会自动读环境变量 ANTHROPIC_API_KEY
        // ==================================================================
        AnthropicClient claude = AnthropicOkHttpClient.fromEnv();

        try {
            mcp.initialize();

            // ==============================================================
            // ① 工具清单：MCP 发现 -> 翻译成 Claude 格式
            //
            // 这一步之后就再也不需要 mcp.listTools() 了。
            // 模型看到的是翻译后的 schema，它根本不知道背后是 MCP。
            // ==============================================================
            List<Tool> claudeTools = mcp.listTools().tools().stream()
                    .map(McpToClaudeTool::toClaudeTool)
                    .toList();

            System.out.println("已加载 " + claudeTools.size() + " 个 MCP 工具："
                    + claudeTools.stream().map(Tool::name).toList());
            System.out.println("─".repeat(60));

            // 对话历史。Claude API 是无状态的，每轮都要把完整历史发过去。
            List<MessageParam> messages = new ArrayList<>();
            messages.add(MessageParam.builder()
                    .role(MessageParam.Role.USER)
                    .content(question)
                    .build());

            // ==============================================================
            // ② agent loop
            // ==============================================================
            for (int turn = 1; turn <= MAX_TURNS; turn++) {

                MessageCreateParams.Builder params = MessageCreateParams.builder()
                        .model(MODEL)
                        // maxTokens 是"思考 + 正文"的总上限。Opus 5 默认开启思考，
                        // 所以要给足余量，否则回答会在半路被截断。
                        .maxTokens(16000L)
                        // 想省钱/降延迟可以下调 effort，代价是推理深度：
                        // .outputConfig(OutputConfig.builder().effort(OutputConfig.Effort.LOW).build())
                        .messages(messages);

                claudeTools.forEach(params::addTool);

                Message response = claude.messages().create(params.build());

                // ---- 安全检查：模型可能因安全策略拒绝 ----
                // 拒绝时 content 可能是空的，下面读 content 前必须先判断。
                if (response.stopReason().orElse(null) == StopReason.REFUSAL) {
                    System.out.println("模型拒绝了本次请求。");
                    response.stopDetails().ifPresent(d ->
                            System.out.println("  类别: " + d.category()));
                    return;
                }

                // ---- 收集这一轮的输出，同时执行工具 ----
                List<ContentBlockParam> assistantBlocks = new ArrayList<>();
                List<ContentBlockParam> toolResults = new ArrayList<>();

                for (ContentBlock block : response.content()) {
                    // toParam() 把响应块转成可以回传的参数块。
                    // 用官方提供的转换，不要手搓——thinking 块的 signature
                    // 必须原样保留，手动重建很容易踩雷。
                    assistantBlocks.add(block.toParam());

                    if (!block.isToolUse()) {
                        block.text().ifPresent(t -> System.out.println("Claude: " + t.text()));
                        continue;
                    }

                    // ======================================================
                    // ③ 模型想看某个工具了 —— 这里就是 MCP 出场的地方
                    // ======================================================
                    ToolUseBlock toolUse = block.toolUse().orElseThrow();
                    Map<String, Object> mcpArgs = toMap(toolUse);

                    System.out.println("  [调用] " + toolUse.name() + " " + mcpArgs);

                    // JsonValue -> Map，然后原样丢给 MCP client。
                    // 注意 model 给的参数没经过任何清洗，server 端的 schema
                    // 校验是唯一防线——这也是它默认开启的原因。
                    McpSchema.CallToolResult mcpResult = mcp.callTool(
                            new McpSchema.CallToolRequest(toolUse.name(), mcpArgs));

                    String resultText = extractText(mcpResult);
                    System.out.println("  [结果] " + resultText);

                    toolResults.add(ContentBlockParam.ofToolResult(
                            ToolResultBlockParam.builder()
                                    .toolUseId(toolUse.id())
                                    .content(resultText)
                                    // 工具报错时要显式标记 is_error，
                                    // 否则模型会把错误信息当成正常返回值继续往下编。
                                    .isError(Boolean.TRUE.equals(mcpResult.isError()))
                                    .build()));
                }

                // 把 assistant 这一轮说的话（含 tool_use 块）记进历史
                messages.add(MessageParam.builder()
                        .role(MessageParam.Role.ASSISTANT)
                        .contentOfBlockParams(assistantBlocks)
                        .build());

                // ==============================================================
                // ⑤ 退出条件
                //
                // 没有工具要调，说明模型认为任务完成了。
                // 用 toolResults.isEmpty() 判断，比只看 stopReason 更稳——
                // 有些情况（比如它既说话又想调工具）stopReason 会有歧义。
                // ==============================================================
                if (toolResults.isEmpty()) {
                    System.out.println("─".repeat(60));
                    System.out.println("(共 " + turn + " 轮)");
                    return;
                }

                // ==============================================================
                // ④ 把工具结果回传，进入下一轮
                //
                // 注意：所有 tool_result 必须装在【同一条】 user 消息里。
                // 拆成多条会悄悄训练模型不再并行调用工具。
                // ==============================================================
                messages.add(MessageParam.builder()
                        .role(MessageParam.Role.USER)
                        .contentOfBlockParams(toolResults)
                        .build());
            }

            System.out.println("达到最大轮数 " + MAX_TURNS + "，强制结束。");

        } finally {
            mcp.closeGracefully();
        }
    }

    /** 把模型的工具入参转成普通 Map，好喂给 MCP。 */
    @SuppressWarnings("unchecked")
    private static Map<String, Object> toMap(ToolUseBlock toolUse) {
        return toolUse._input().convert(Map.class);
    }

    /** CallToolResult.content() 是 Content 列表，文本在 TextContent 里。 */
    private static String extractText(McpSchema.CallToolResult result) {
        StringBuilder sb = new StringBuilder();
        for (McpSchema.Content c : result.content()) {
            if (c instanceof McpSchema.TextContent t) {
                sb.append(t.text());
            }
        }
        return sb.toString();
    }
}
```

### 3.1 `StdioLifecycle` —— 进程生命周期

> 解决官方 SDK 的一个坑：stdio server 在 stdin 关闭后不会自己退出，会导致孤儿进程。这里通过包装 System.in 检测 EOF。
>
> **文件路径**：`src/main/java/com/example/mcp/core/StdioLifecycle.java`

```java
package com.example.mcp.core;

import io.modelcontextprotocol.json.McpJsonMapper;
import io.modelcontextprotocol.server.transport.StdioServerTransportProvider;
import io.modelcontextprotocol.spec.McpServerTransportProvider;

import java.io.FilterInputStream;
import java.io.IOException;
import java.io.InputStream;
import java.util.concurrent.CountDownLatch;

/**
 * STDIO server 的生命周期管理。
 *
 * ══════════════════════════════════════════════════════════════════
 *  解决什么问题
 * ══════════════════════════════════════════════════════════════════
 *
 * MCP 官方 SDK 的 stdio server 有个容易被忽略的行为：
 * **主线程一旦挂住就永远不退出，即使 stdin 已经关闭。**
 *
 * 后果有两个：
 *
 *   1. 孤儿进程。客户端崩了、被 kill 了、没调 closeGracefully()，
 *      server 进程会一直赖在任务管理器里。跑几十次就堆一堆。
 *
 *   2. 退出码非零。客户端只能强杀进程，Windows 上强杀的退出码是 1，
 *      于是客户端每次都打印 "MCP server process failed with code 1" ——
 *      明明是一次正常关闭，看起来却像崩溃。
 *
 * 根因是：SDK 没有暴露"会话已关闭"的回调，
 * 而 server 的 main 通常写成 `new CountDownLatch(1).await()`（永久阻塞）。
 *
 * ══════════════════════════════════════════════════════════════════
 *  思路
 * ══════════════════════════════════════════════════════════════════
 *
 * 既然 SDK 不给回调，就自己造一个信号：
 * 把 System.in 包一层，一旦读到 EOF（-1）就释放 latch。
 *
 * stdin 关闭 == 客户端已断开，这是 stdio 传输下最可靠的断连信号。
 *
 * StdioServerTransportProvider 正好有个接收自定义流的构造函数，
 * 所以这个包装可以无侵入地塞进去。
 */
public final class StdioLifecycle {

    private StdioLifecycle() {
    }

    /**
     * 创建一个带断连感知的传输。
     */
    public static Handle create(McpJsonMapper jsonMapper) {
        CountDownLatch eof = new CountDownLatch(1);
        McpServerTransportProvider provider = new StdioServerTransportProvider(
                jsonMapper,
                new EofAwareInputStream(System.in, eof),
                System.out);
        return new Handle(provider, eof);
    }

    public record Handle(McpServerTransportProvider provider, CountDownLatch eof) {

        /**
         * 阻塞，直到客户端断开（stdin EOF）。
         *
         * 返回后应该调用 server.closeGracefully() 再让 main 结束，
         * 这样 JVM 会以退出码 0 正常退出。
         */
        public void awaitClientDisconnect() {
            try {
                eof.await();
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }
    }

    /**
     * 转发所有读取，顺手盯住 EOF。
     *
     * 注意要覆盖 read() 和 read(byte[], int, int) 两个重载——
     * 具体走哪个取决于调用方，漏掉一个就检测不到 EOF。
     */
    private static final class EofAwareInputStream extends FilterInputStream {

        private final CountDownLatch eof;

        EofAwareInputStream(InputStream in, CountDownLatch eof) {
            super(in);
            this.eof = eof;
        }

        @Override
        public int read() throws IOException {
            int b = super.read();
            if (b == -1) {
                eof.countDown();
            }
            return b;
        }

        @Override
        public int read(byte[] buf, int off, int len) throws IOException {
            int n = super.read(buf, off, len);
            if (n == -1) {
                eof.countDown();
            }
            return n;
        }
    }
}
```

### 3.2 `McpAgent` —— 可复用 agent loop

> 从 Step4 抽出来的生产级版本。比教学版多了三件事：客户端懒加载、工具结果长度上限、工具崩溃时的兜底。
>
> **文件路径**：`src/main/java/com/example/mcp/core/McpAgent.java`

```java
package com.example.mcp.core;

import com.anthropic.client.AnthropicClient;
import com.anthropic.client.okhttp.AnthropicOkHttpClient;
import com.anthropic.models.messages.ContentBlock;
import com.anthropic.models.messages.ContentBlockParam;
import com.anthropic.models.messages.Message;
import com.anthropic.models.messages.MessageCreateParams;
import com.anthropic.models.messages.MessageParam;
import com.anthropic.models.messages.StopReason;
import com.anthropic.models.messages.Tool;
import com.anthropic.models.messages.ToolResultBlockParam;
import com.anthropic.models.messages.ToolUseBlock;

import com.example.mcp.step3.McpToClaudeTool;

import io.modelcontextprotocol.client.McpClient;
import io.modelcontextprotocol.client.McpSyncClient;
import io.modelcontextprotocol.client.transport.ServerParameters;
import io.modelcontextprotocol.client.transport.StdioClientTransport;
import io.modelcontextprotocol.json.McpJsonMapper;
import io.modelcontextprotocol.json.jackson3.JacksonMcpJsonMapperSupplier;
import io.modelcontextprotocol.spec.McpSchema;

import java.time.Duration;
import java.util.ArrayList;
import java.util.List;
import java.util.Map;
import java.util.function.Consumer;

/**
 * 可复用的 agent loop：接一个 MCP Server，然后对话。
 *
 * 和 step4/AgentMain 的关系：
 *   step4/AgentMain 把循环写在 main 里，是为了教学——
 *   你可以在一屏内看完整条链路，不用跳文件。
 *   这个类是把同一套逻辑抽出来给实际项目用。
 *
 * 用法：
 *   try (McpAgent agent = McpAgent.connect("com.example.mcp.db.DbMcpServer")) {
 *       agent.ask("9 月份领用最多的备件是什么？");
 *   }
 */
public final class McpAgent implements AutoCloseable {

    private static final String MODEL = "claude-opus-5";

    /** 防御性上限：模型偶尔会陷入循环。 */
    private static final int MAX_TURNS = 12;

    /**
     * 回灌给模型的工具结果长度上限。
     *
     * 为什么需要这个？因为工具结果会原样进入对话历史，
     * 而对话历史每一轮都要完整重发。一个 200 行的表格塞进去，
     * 之后每一轮都在为它付 input token——成本会指数级放大。
     *
     * 真实项目里更常见的做法是：只回传摘要 + 让模型按需再查。
     */
    private static final int MAX_TOOL_RESULT_CHARS = 4_000;

    private final McpSyncClient mcp;
    private final List<Tool> tools;
    private final Consumer<String> out;

    /**
     * Claude 客户端【懒加载】。
     *
     * 这样 connect() 不需要 ANTHROPIC_API_KEY ——
     * 你可以先只连 MCP 自检（--dry-run），确认工具都加载对了，
     * 再去花 API 的钱。顺便也让"连不上 server"和"没配 Key"
     * 这两类错误分开了，排查起来清楚得多。
     */
    private AnthropicClient claude;

    /** 模型最近一次输出的正文，循环结束时返回。 */
    private String lastText = "";

    private McpAgent(McpSyncClient mcp, List<Tool> tools, Consumer<String> out) {
        this.mcp = mcp;
        this.tools = tools;
        this.out = out;
    }

    private AnthropicClient claude() {
        if (claude == null) {
            claude = AnthropicOkHttpClient.fromEnv();
        }
        return claude;
    }

    /**
     * 连上一个 MCP Server。
     *
     * @param serverMainClass server 的主类全名，比如 "com.example.mcp.db.DbMcpServer"。
     *                        这里刻意用「类名」而不是「命令」，是因为本教程的所有
     *                        server 都是同一个 Java 工程里的类。真实场景通常是
     *                        ServerParameters.builder("npx").args("-y", "@xxx/mcp-server")
     *                        这种形式——MCP 不关心 server 是什么语言写的。
     */
    public static McpAgent connect(String serverMainClass) {
        return connect(serverMainClass, System.out::println);
    }

    public static McpAgent connect(String serverMainClass, Consumer<String> out) {
        McpJsonMapper jsonMapper = new JacksonMcpJsonMapperSupplier().get();

        ServerParameters serverParams = ServerParameters.builder("java")
                .args("-Dfile.encoding=UTF-8",
                      "-Dstdout.encoding=UTF-8",
                      "-Dstderr.encoding=UTF-8",
                      "-classpath", System.getProperty("java.class.path"),
                      serverMainClass)
                .build();

        McpSyncClient mcp = McpClient.sync(new StdioClientTransport(serverParams, jsonMapper))
                // 数据库查询可能慢，超时给宽一点
                .requestTimeout(Duration.ofSeconds(60))
                .build();

        // 握手失败会在这里抛异常，越早失败越好
        mcp.initialize();

        // MCP 发现 → Claude 工具格式
        List<Tool> tools = mcp.listTools().tools().stream()
                .map(McpToClaudeTool::toClaudeTool)
                .toList();

        out.accept("已连接 " + mcp.getServerInfo().name()
                + "，加载 " + tools.size() + " 个工具："
                + tools.stream().map(Tool::name).toList());

        return new McpAgent(mcp, tools, out);
    }

    /**
     * 问一个问题，跑完整个 agent loop。
     *
     * @return 模型的最终回答；被拒绝或达到轮数上限时返回空串
     */
    public String ask(String question) {
        out.accept("");
        out.accept("用户: " + question);

        List<MessageParam> messages = new ArrayList<>();
        messages.add(MessageParam.builder()
                .role(MessageParam.Role.USER)
                .content(question)
                .build());

        for (int turn = 1; turn <= MAX_TURNS; turn++) {

            MessageCreateParams.Builder params = MessageCreateParams.builder()
                    .model(MODEL)
                    // Claude Opus 5 默认开启思考，maxTokens 是「思考 + 正文」的总上限，
                    // 给紧会让回答半路被截断
                    .maxTokens(16000L)
                    .messages(messages);
            tools.forEach(params::addTool);

            Message response = claude().messages().create(params.build());

            // 安全策略可能拒绝。拒绝时 content 可能是空的，必须先判断再读。
            if (response.stopReason().orElse(null) == StopReason.REFUSAL) {
                out.accept("[模型拒绝了本次请求]");
                response.stopDetails().ifPresent(d -> out.accept("  类别: " + d.category()));
                return "";
            }

            List<ContentBlockParam> assistantBlocks = new ArrayList<>();
            List<ContentBlockParam> toolResults = new ArrayList<>();

            for (ContentBlock block : response.content()) {
                // 用官方 toParam()，不要手搓——thinking 块的 signature
                // 必须逐字节原样保留，手动重建会破坏它
                assistantBlocks.add(block.toParam());

                if (!block.isToolUse()) {
                    block.text().ifPresent(t -> finalTextHolder(out, t.text()));
                    continue;
                }

                ToolUseBlock toolUse = block.toolUse().orElseThrow();
                Map<String, Object> mcpArgs = toolUse._input().convert(Map.class);

                out.accept("  [调用] " + toolUse.name() + " " + summarizeArgs(mcpArgs));

                toolResults.add(invokeMcpTool(toolUse, mcpArgs));
            }

            messages.add(MessageParam.builder()
                    .role(MessageParam.Role.ASSISTANT)
                    .contentOfBlockParams(assistantBlocks)
                    .build());

            // 没有工具要调 = 任务完成
            if (toolResults.isEmpty()) {
                out.accept("（共 " + turn + " 轮）");
                return lastText;
            }

            // 所有 tool_result 必须在同一条 user 消息里。
            // 拆成多条会悄悄训练模型不再并行调用工具。
            messages.add(MessageParam.builder()
                    .role(MessageParam.Role.USER)
                    .contentOfBlockParams(toolResults)
                    .build());
        }

        out.accept("[达到最大轮数 " + MAX_TURNS + "，强制结束]");
        return lastText;
    }

    /** 已加载的工具名。用于自检，不需要调用模型。 */
    public List<String> toolNames() {
        return tools.stream().map(Tool::name).toList();
    }

    // ------------------------------------------------------------------

    private void finalTextHolder(Consumer<String> out, String text) {
        lastText = text;
        out.accept(text);
    }

    /** 调 MCP 工具，把结果包成 tool_result 块。 */
    private ContentBlockParam invokeMcpTool(ToolUseBlock toolUse, Map<String, Object> args) {
        try {
            McpSchema.CallToolResult r = mcp.callTool(
                    new McpSchema.CallToolRequest(toolUse.name(), args));

            String text = extractText(r);
            boolean isError = Boolean.TRUE.equals(r.isError());

            out.accept("  [" + (isError ? "错误" : "结果") + "] " + firstLines(text, 6));

            return ContentBlockParam.ofToolResult(ToolResultBlockParam.builder()
                    .toolUseId(toolUse.id())
                    .content(cap(text))
                    // 必须显式标记错误，否则模型会把报错当成正常返回值继续编
                    .isError(isError)
                    .build());

        } catch (Exception e) {
            // 工具本身崩了（server 挂了、超时了），也要回一条 tool_result，
            // 否则对话会卡在"有个 tool_use 没有对应结果"的非法状态
            String msg = "工具调用失败: " + e.getMessage();
            out.accept("  [错误] " + msg);
            return ContentBlockParam.ofToolResult(ToolResultBlockParam.builder()
                    .toolUseId(toolUse.id())
                    .content(msg)
                    .isError(true)
                    .build());
        }
    }

    private static String cap(String text) {
        if (text.length() <= MAX_TOOL_RESULT_CHARS) {
            return text;
        }
        return text.substring(0, MAX_TOOL_RESULT_CHARS)
                + "\n…（结果过长已截断。如需完整数据，请缩小查询范围或使用聚合）";
    }

    private static String extractText(McpSchema.CallToolResult result) {
        StringBuilder sb = new StringBuilder();
        for (McpSchema.Content c : result.content()) {
            if (c instanceof McpSchema.TextContent t) {
                sb.append(t.text());
            }
        }
        return sb.toString();
    }

    private static String summarizeArgs(Map<String, Object> args) {
        String s = String.valueOf(args);
        return s.length() > 200 ? s.substring(0, 200) + "…" : s;
    }

    private static String firstLines(String text, int n) {
        String[] lines = text.split("\n");
        StringBuilder sb = new StringBuilder();
        for (int i = 0; i < Math.min(n, lines.length); i++) {
            if (!lines[i].isBlank()) {
                sb.append(lines[i].strip());
                if (i < n - 1 && i < lines.length - 1) {
                    sb.append(" / ");
                }
            }
        }
        String s = sb.toString();
        return s.length() > 300 ? s.substring(0, 300) + "…"
                : (lines.length > n ? s + " …（共 " + lines.length + " 行）" : s);
    }

    @Override
    public void close() {
        // 不调用的话，server 子进程会赖着不走
        mcp.closeGracefully();
    }
}
```

### 4.1 `Db` —— 数据源层

> ★ 唯一需要改动的层。演示模式自带一套刻意设计过的测试数据（含 5000 行大表，用来验证限流机制真的生效）。
>
> **文件路径**：`src/main/java/com/example/mcp/db/Db.java`

```java
package com.example.mcp.db;

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.SQLException;
import java.sql.Statement;

/**
 * 【数据源层】—— 整个工程里唯一需要改动的层。
 *
 * ══════════════════════════════════════════════════════════════════
 *  ★ 铁律：先接测试库，永远不要直接接生产库
 * ══════════════════════════════════════════════════════════════════
 *
 * 即使你做了只读账号 + SQL 白名单 + 超时，第一次跑也请接测试库。
 * 理由不是"怕它改数据"（只读账号已经挡住了），而是：
 *
 *   1. 你不知道模型会写出什么查询。一条没加索引的 JOIN
 *      在千万行表上能把生产库拖垮——只读不代表无害。
 *   2. 你不知道模型会查出什么数据。它可能把客户手机号、
 *      工资、身份证号直接返回并写进对话历史。
 *   3. 你需要先看清楚"工具描述写得够不够清楚"，
 *      这只有在真实结构上跑一遍才知道。
 *
 * ──────────────────────────────────────────────────────────────────
 *  两种模式
 * ──────────────────────────────────────────────────────────────────
 *
 * 【演示模式】（默认）
 *   用内置的 H2 内存库，自带一套贴近真实的测试数据。
 *   每次启动重新建，改坏了重启即可，零副作用。
 *   直接跑，不需要任何配置。
 *
 * 【接真实测试库】
 *   设置环境变量即可，代码一行不用改：
 *
 *     DB_URL=jdbc:postgresql://test-db:5432/sparedb
 *     DB_USER=mcp_readonly
 *     DB_PASSWORD=******
 *
 *   设了 DB_URL 就自动进入这个模式，不会再建演示数据。
 *   这个账号必须是【只读】的——这不是可选项。
 */

        return ENV_URL == null || ENV_URL.isBlank();
    }

    /**
     * 管理连接用的 URL —— 只在演示模式下用于建表灌数据。
     *
     * DB_CLOSE_DELAY=-1 让内存库在整个 JVM 生命周期内存活。
     * 不加这个，最后一个连接关闭时库就没了。
     */
    private static final String ADMIN_URL = "jdbc:h2:mem:sparedb;DB_CLOSE_DELAY=-1";
    private static final String ADMIN_USER = "sa";
    private static final String ADMIN_PASSWORD = "";

    /**
     * ★ 只读连接。
     *

     *
     * 注意演示模式的 URL 里【没有】DB_CLOSE_DELAY —— 这是个真踩过的坑：
     * H2 里 SET DB_CLOSE_DELAY 需要管理员权限，只读账号带上它会直接连接失败：
     *   "Admin rights are required for this operation: SET DB_CLOSE_DELAY -1"
```

### 4.2 `SqlGuard` —— SQL 安全层

> ★ 核心。掩码 + 分词 + 白名单 + LIMIT 加固。手写状态机而不是正则，是为了正确处理转义引号和注释嵌套。

```java
package com.example.mcp.db;

import java.util.List;

 * 【安全层】SQL 校验器 —— 这是整个方案里最需要认真对待的代码。
 *
 * ══════════════════════════════════════════════════════════════════
 *  先读这段，再读代码
 * ══════════════════════════════════════════════════════════════════
 *
 * 这个类的职责是"挡住危险的 SQL"。但你必须清楚它的定位：
 *
 *   它是【第二道】墙，不是第一道，也不是唯一一道。
 *
 * 三道墙的分工：
 *   ① 数据库只读账号   ← 唯一不依赖"我的代码写得对"的一道，最重要
 *   ② 本类（SQL 校验）  ← 提供清晰错误信息，挡住绝大多数误操作
 *   ③ 超时 + 行数上限   ← 防止模型写出拖垮数据库的查询
 *
 * 为什么不能只靠 ②？
 *
 * 因为**用正则/分词来判断 SQL 安全性，理论上不可能做到完备**。
 * SQL 语法极其复杂，任何手写的解析器都有绕过路径。举个真实的例子：
 * 不同数据库的方言差异、嵌套注释、Unicode 同形字、
 * 存储过程里的动态 SQL……你不可能全部枚举。
 *
 * 所以正确的态度是：
 *   ② 用来挡"模型不小心写错"（占 99%），
 *   ① 用来挡"有人故意绕过"（占 1%，但后果严重）。
 *
 * 如果你只做了一件事，请做 ①。
 * ══════════════════════════════════════════════════════════════════
 */
public final class SqlGuard {

    /** 单次查询最多返回多少行。防止 SELECT * FROM 大表把内存打爆。 */
    public static final int MAX_ROWS = 200;

    /** SQL 最大长度。防止超长 SQL 攻击或模型跑飞。 */
    private static final int MAX_SQL_LENGTH = 8_000;

    /**
     * 禁止出现的关键字。
     *
     * 注意这是在【掩码后】的 SQL 上做整词匹配，所以：
     *   - 字符串字面量里的 'delete' 不会误伤（已被掩码成空格）
     *   - 列名 delete_flag 不会误伤（整词匹配，不是子串匹配）
     *
     * INTO 要特别说一下：SELECT ... INTO 会创建新表，是个写操作。
     * 这类"看起来是查询其实是写"的语法最容易漏。
     */
    private static final Set<String> BANNED_KEYWORDS = Set.of(
            // DML
            "INSERT", "UPDATE", "DELETE", "MERGE", "UPSERT", "REPLACE", "TRUNCATE",
            // DDL
            "CREATE", "ALTER", "DROP", "RENAME", "COMMENT",
            // DCL / 权限
            "GRANT", "REVOKE",
            // 会话与事务控制
            "SET", "CALL", "EXEC", "EXECUTE", "PREPARE", "DEALLOCATE",
            // 写表语法
            "INTO",
            // 锁
            "LOCK", "UNLOCK",
            // H2 特有的危险函数/语句（能读写文件系统）
            "RUNSCRIPT", "SCRIPT", "BACKUP", "RESTORE", "CSVWRITE", "CSVREAD",
            "FILE_READ", "FILE_WRITE", "LINK_SCHEMA", "SHUTDOWN", "ATTACH", "DETACH",
            "CHECKPOINT", "EXPORT", "IMPORT"
    );

    /** 只允许以这些关键字开头。WITH 是 CTE，本质还是查询。 */
    private static final Set<String> ALLOWED_LEADING = Set.of("SELECT", "WITH");

    private static final Pattern LIMIT_PATTERN =
            Pattern.compile("(?i)\\blimit\\s+(\\d+)");

    private SqlGuard() {
    }

    /**
     * 校验结果。
     *
     * @param ok    是否放行
     * @param sql   放行时返回的、已加固的 SQL（可能被追加/收敛了 LIMIT）
     * @param reason 拒绝原因，会原样回给模型——这点很重要，
     *               模型看到具体原因才知道怎么改，而不是瞎猜
     */
    public record Verdict(boolean ok, String sql, String reason) {

        static Verdict pass(String sql) {
            return new Verdict(true, sql, null);
        }

        static Verdict reject(String reason) {
            return new Verdict(false, null, reason);
        }
    }

    /**
     * 校验并加固一条 SQL。
     *
     * @param rawSql 模型生成的原始 SQL，**完全不可信**
     */
    public static Verdict inspect(String rawSql) {
        if (rawSql == null || rawSql.isBlank()) {
            return Verdict.reject("SQL 为空。");
        }

        String sql = rawSql.strip();

        // 去掉结尾的分号（单条语句末尾带分号是合法的，不该报错）
        while (sql.endsWith(";")) {
            sql = sql.substring(0, sql.length() - 1).stripTrailing();
        }

        if (sql.isEmpty()) {
            return Verdict.reject("SQL 为空。");
        }

        if (sql.length() > MAX_SQL_LENGTH) {
            return Verdict.reject("SQL 过长（超过 " + MAX_SQL_LENGTH + " 字符）。");
        }

        // ---------------------------------------------------------------
        // 掩码：把字符串字面量、引号标识符、注释全部替换成等长空格。
        //
        // 为什么要"等长"？因为这样掩码串和原串的字符下标一一对应，
        // 后面改 LIMIT 时可以直接用掩码里找到的位置去改原串。
        //
        // 为什么要掩码而不是直接正则匹配？
        // 因为 SELECT '这里写 DELETE 不算数' 里的 DELETE 是数据不是语法。
        // 不掩码就会误伤，或者反过来被构造的字符串骗过。
        // ---------------------------------------------------------------
        String masked = mask(sql);

        // 掩码后再查分号：能挡住 SELECT 1; DELETE FROM t 这种堆叠语句
        if (masked.indexOf(';') >= 0) {
            return Verdict.reject("不允许一次执行多条 SQL 语句。请只提交一条 SELECT。");
        }

        List<String> tokens = tokenize(masked);

        if (tokens.isEmpty()) {
            return Verdict.reject("SQL 为空。");
        }

        String leading = tokens.get(0);
        if (!ALLOWED_LEADING.contains(leading)) {
            return Verdict.reject(
                    "只允许 SELECT 查询，当前以 " + leading + " 开头。"
                            + "如果你需要看表结构，请使用 describe_table 工具。");
        }

        for (String token : tokens) {
            if (BANNED_KEYWORDS.contains(token)) {
                return Verdict.reject(
                        "SQL 中包含禁止的关键字：" + token + "。本工具是只读的，只能执行 SELECT 查询。");
            }
        }

        // ---------------------------------------------------------------
        // 加固 LIMIT
        //
        // 模型经常忘记写 LIMIT，直接 SELECT * FROM 一张百万行的表。
        // 这里做两件事：没写就补上；写了但太大就收敛到上限。
        // ---------------------------------------------------------------
        String hardened = enforceLimit(sql, masked);
        return Verdict.pass(hardened);
    }

    /**
     * 把字符串字面量 / 引号标识符 / 注释替换成等长空格。
     *
     * 这是一个手写的小状态机。相比正则，它能正确处理：
     *   - '' 形式的转义引号（SQL 标准里用两个单引号表示一个单引号）
     *   - 未闭合的引号（截断输入）
     *   - 注释嵌套引号、引号里包注释
     */
    static String mask(String sql) {
        char[] out = sql.toCharArray();
        int i = 0;
        int n = sql.length();

        while (i < n) {
            char c = sql.charAt(i);

            if (c == '\'') {
                // 单引号字符串字面量
                out[i] = ' ';
                i++;
                while (i < n) {
                    if (sql.charAt(i) == '\'') {
                        if (i + 1 < n && sql.charAt(i + 1) == '\'') {
                            // 转义的引号，继续留在字符串里
                            out[i] = ' ';
                            out[i + 1] = ' ';
                            i += 2;
                            continue;
                        }
                        out[i] = ' ';
                        i++;
                        break;
                    }
                    out[i] = ' ';
                    i++;
                }

            } else if (c == '"') {
                // 双引号标识符（如 "my""column"）
                out[i] = ' ';
                i++;
                while (i < n) {
                    if (sql.charAt(i) == '"') {
                        out[i] = ' ';
                        i++;
                        break;
                    }
                    out[i] = ' ';
                    i++;
                }

            } else if (c == '-' && i + 1 < n && sql.charAt(i + 1) == '-') {
                // 行注释直到行尾
                while (i < n && sql.charAt(i) != '\n') {
                    out[i] = ' ';
                    i++;
                }

            } else if (c == '/' && i + 1 < n && sql.charAt(i + 1) == '*') {
                // 块注释
                out[i] = ' ';
                out[i + 1] = ' ';
                i += 2;
                while (i + 1 < n && !(sql.charAt(i) == '*' && sql.charAt(i + 1) == '/')) {
                    out[i] = ' ';
                    i++;
                }
                if (i + 1 < n) {
                    out[i] = ' ';
                    out[i + 1] = ' ';
                    i += 2;
                } else {
                    while (i < n) {
                        out[i] = ' ';
                        i++;
                    }
                }

            } else {
                i++;
            }
        }

        return new String(out);
    }

    /** 按非标识符字符切词，全部转大写。 */
    private static List<String> tokenize(String masked) {
        return Pattern.compile("[^A-Za-z0-9_]+")
                .splitAsStream(masked.toUpperCase(Locale.ROOT))
                .filter(t -> !t.isEmpty())
                .toList();
    }

    /**
     * 保证 SQL 带一个不超过 MAX_ROWS 的 LIMIT。
     *
     * 利用掩码串和原串等长的特性，在掩码里定位、在原串上修改。
     */
    private static String enforceLimit(String sql, String masked) {
        Matcher m = LIMIT_PATTERN.matcher(masked);

        if (m.find()) {
            // 已经有 LIMIT 了，把过大的数字收敛下来
            int start = m.start(1);
            int end = m.end(1);
            try {
                long current = Long.parseLong(sql.substring(start, end));
                if (current > MAX_ROWS) {
                    return sql.substring(0, start) + MAX_ROWS + sql.substring(end);
                }
            } catch (NumberFormatException ignored) {
                // 数字长得离谱（超出 long），直接换成上限
                return sql.substring(0, start) + MAX_ROWS + sql.substring(end);
            }
            return sql;
        }

        // FETCH FIRST n ROWS ONLY 也是一种限流语法，尊重它
        if (Pattern.compile("(?i)\\bfetch\\b").matcher(masked).find()) {
            return sql;
        }

        return sql + " LIMIT " + MAX_ROWS;
    }
}
```

### 4.3 `AuditLog` —— 审计日志

> 记录每次工具调用，包含被拒绝的。被拒绝的比成功的更有信息量。
>
> **文件路径**：`src/main/java/com/example/mcp/db/AuditLog.java`

```java
package com.example.mcp.db;

import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.StandardOpenOption;
import java.time.LocalDateTime;
import java.time.format.DateTimeFormatter;

/**
 * 【安全层·审计】把每一次工具调用记下来。
 *
 * 为什么这个不能省？
 *
 * 因为 agent 和普通程序有个本质区别：**它的行为是模型决定的，你无法预知**。
 * 你没法像 review 代码那样 review 模型下一步要干什么。
 *
 * 所以出事的时候（查错了数据、SQL 把库拖慢了、模型被提示注入操纵了），
 * 你唯一能依靠的就是"它到底干了什么"的记录。
 *
 * 记录内容刻意包含了**被拒绝的请求**——被拒绝的比成功的更有信息量，
 * 它告诉你模型想干什么但没干成。
 */
public final class AuditLog {

    private static final DateTimeFormatter TS =
            DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss.SSS");

    private static final Path LOG_FILE = Path.of(
            System.getenv().getOrDefault("MCP_AUDIT_FILE", "mcp-audit.log"));

    private AuditLog() {
    }

    /**
     * 记一条。
     *
     * @param tool     工具名
     * @param sql      原始 SQL（模型生成的那份，不是加固后的——回溯时要看原样）
     * @param allowed  是否放行
     * @param detail   拒绝原因，或成功时的结果摘要
     * @param millis   耗时毫秒
     */
    public static synchronized void record(String tool, String sql,
                                           boolean allowed, String detail, long millis) {
        String line = "%s | %-14s | %-4s | %5dms | %s | %s%n".formatted(
                LocalDateTime.now().format(TS),
                tool,
                allowed ? "PASS" : "DENY",
                millis,
                oneLine(sql),
                oneLine(detail));

        // 审计日志写到文件，不是 stdout —— stdout 是 MCP 的协议通道
        try {
            Files.writeString(LOG_FILE, line, StandardCharsets.UTF_8,
                    StandardOpenOption.CREATE, StandardOpenOption.APPEND);
        } catch (IOException e) {
            // 审计失败不能影响主流程，但必须让人看见
            System.err.println("[audit] 写入失败: " + e.getMessage());
        }
    }

    /** 压成单行，避免日志被换行撑爆。 */
    private static String oneLine(String s) {
        if (s == null) {
            return "-";
        }
        String flat = s.replaceAll("\\s+", " ").strip();
        return flat.length() > 300 ? flat.substring(0, 300) + "…" : flat;
    }

    public static Path logFile() {
        return LOG_FILE.toAbsolutePath();
    }
}
```

### 4.4 `SchemaIntrospector` —— 表结构自省

> 把数据库的中文注释读出来给模型看。这是让 AI 查库真正好用的关键。
>
> **文件路径**：`src/main/java/com/example/mcp/db/SchemaIntrospector.java`

```java
package com.example.mcp.db;

import java.sql.Connection;
import java.sql.DatabaseMetaData;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.sql.Statement;
import java.util.ArrayList;
import java.util.LinkedHashSet;
import java.util.List;
import java.util.Locale;
import java.util.Set;
import java.util.regex.Pattern;

/**
 * 【工具层·支撑】把数据库结构读出来，喂给模型。
 *
 * 为什么这件事值得单独写一个类？
 *
 * 因为**模型看不见你的库**。你问它"上个月领用最多的备件"，
 * 它不知道有 spare_usage 这张表，不知道字段叫 used_at 而不是 create_time，
 * 不知道 part_id 要 JOIN 到 spare_part。
 *
 * 它唯一的信息来源就是你通过工具给它的描述。
 *
 * 所以 list_tables / describe_table 这两个工具的质量，
 * 直接决定了整个 MCP 好不好用——比 run_query 本身还重要。
 * 模型 SQL 写得对不对，九成取决于它有没有看懂表结构。
 *
 * 这也是为什么 Db.java 里那些 COMMENT ON 不是装饰。
 */
public final class SchemaIntrospector {

    /** 合法标识符。用来防止表名被拼进 SQL 时注入。 */
    private static final Pattern SAFE_IDENTIFIER = Pattern.compile("[A-Za-z_][A-Za-z0-9_]*");

    private SchemaIntrospector() {
    }

    /**
     * 列出所有表：表名 + 行数 + 中文说明。
     */
    public static String listTables(Connection conn) throws SQLException {
        DatabaseMetaData meta = conn.getMetaData();

        List<String[]> tables = new ArrayList<>();   // {name, remark}

        try (ResultSet rs = meta.getTables(null, conn.getSchema(), "%", new String[]{"TABLE"})) {
            while (rs.next()) {
                tables.add(new String[]{
                        rs.getString("TABLE_NAME"),
                        rs.getString("REMARKS")
                });
            }
        }

        if (tables.isEmpty()) {
            return "当前数据库没有任何表。";
        }

        StringBuilder sb = new StringBuilder();
        sb.append("共 ").append(tables.size()).append(" 张表：\n\n");
        sb.append("| 表名 | 行数 | 说明 |\n");
        sb.append("|---|---:|---|\n");

        for (String[] t : tables) {
            sb.append("| ").append(t[0])
              .append(" | ").append(countRows(conn, t[0]))
              .append(" | ").append(blankToDash(t[1]))
              .append(" |\n");
        }

        sb.append("\n用 describe_table 查看某张表的字段结构。");
        return sb.toString();
    }

    /**
     * 描述一张表的字段结构。
     */
    public static String describeTable(Connection conn, String rawTableName) throws SQLException {
        if (rawTableName == null || rawTableName.isBlank()) {
            return "错误：必须提供表名。可用 list_tables 查看有哪些表。";
        }

        String table = rawTableName.strip();

        // 先去元数据里找真实表名，顺便做大小写归一
        // （H2/PostgreSQL 里未加引号的标识符会被转成小写或大写，
        //   模型不知道这个细节，我们替它兜住）
        String actualTable = resolveTableName(conn, table);
        if (actualTable == null) {
            return "错误：找不到表 " + table + "。可用 list_tables 查看有哪些表。";
        }

        DatabaseMetaData meta = conn.getMetaData();

        // 主键列
        Set<String> pkColumns = new LinkedHashSet<>();
        try (ResultSet rs = meta.getPrimaryKeys(null, conn.getSchema(), actualTable)) {
            while (rs.next()) {
                pkColumns.add(rs.getString("COLUMN_NAME"));
            }
        }

        StringBuilder sb = new StringBuilder();
        sb.append("表 ").append(actualTable);

        String tableRemark = tableRemark(conn, actualTable);
        if (tableRemark != null && !tableRemark.isBlank()) {
            sb.append(" —— ").append(tableRemark);
        }
        sb.append("\n\n");

        sb.append("| 字段名 | 类型 | 可空 | 主键 | 说明 |\n");
        sb.append("|---|---|---|---|---|\n");

        int count = 0;
        try (ResultSet rs = meta.getColumns(null, conn.getSchema(), actualTable, "%")) {
            while (rs.next()) {
                String name = rs.getString("COLUMN_NAME");
                String type = rs.getString("TYPE_NAME");
                int size = rs.getInt("COLUMN_SIZE");
                boolean nullable = rs.getInt("NULLABLE") != DatabaseMetaData.columnNoNulls;
                String remark = rs.getString("REMARKS");

                // 只给变长类型带长度，INTEGER 这类带上反而干扰阅读
                String typeDisplay = needsLength(type) && size > 0
                        ? type + "(" + size + ")"
                        : type;

                sb.append("| ").append(name)
                  .append(" | ").append(typeDisplay)
                  .append(" | ").append(nullable ? "是" : "否")
                  .append(" | ").append(pkColumns.contains(name) ? "✓" : "")
                  .append(" | ").append(blankToDash(remark))
                  .append(" |\n");
                count++;
            }
        }

        sb.append("\n共 ").append(count).append(" 个字段。");
        if (count > 0 && sb.indexOf("—") < 0) {
            // 提醒：注释缺失会让模型猜字段含义
            sb.append("\n\n提示：本表多数字段缺少注释，模型需要靠字段名推断含义，容易出错。");
        }
        return sb.toString();
    }

    // ------------------------------------------------------------------
    // 内部工具
    // ------------------------------------------------------------------

    /** 在元数据里找出真实表名，做大小写无关匹配。 */
    private static String resolveTableName(Connection conn, String input) throws SQLException {
        DatabaseMetaData meta = conn.getMetaData();
        try (ResultSet rs = meta.getTables(null, conn.getSchema(), "%", new String[]{"TABLE"})) {
            while (rs.next()) {
                String name = rs.getString("TABLE_NAME");
                if (name.equalsIgnoreCase(input)) {
                    return name;
                }
            }
        }
        return null;
    }

    private static String tableRemark(Connection conn, String table) throws SQLException {
        DatabaseMetaData meta = conn.getMetaData();
        try (ResultSet rs = meta.getTables(null, conn.getSchema(), table, new String[]{"TABLE"})) {
            if (rs.next()) {
                return rs.getString("REMARKS");
            }
        }
        return null;
    }

    /**
     * 数一下行数。
     *
     * 注意：这里对每张表做全表 COUNT，表大了会很慢。
     * 生产环境应该改用数据库的统计信息（PostgreSQL 的 pg_class.reltuples、
     * MySQL 的 information_schema.TABLES.TABLE_ROWS），拿到的是近似值但零开销。
     * 演示库小，直接数最准确。
     */
    private static String countRows(Connection conn, String table) {
        // 表名来自元数据而非用户输入，但仍做一次严格校验，
        // 保证拼接进 SQL 的一定是合法标识符
        if (!SAFE_IDENTIFIER.matcher(table).matches()) {
            return "?";
        }
        String sql = "SELECT COUNT(*) FROM \"" + table.toUpperCase(Locale.ROOT) + "\"";
        try (Statement st = conn.createStatement();
             ResultSet rs = st.executeQuery(sql)) {
            return rs.next() ? String.valueOf(rs.getLong(1)) : "?";
        } catch (SQLException e) {
            return "?";
        }
    }

    /** INTEGER 这种定长类型不需要显示长度。 */
    private static boolean needsLength(String type) {
        String t = type.toUpperCase(Locale.ROOT);
        return t.contains("CHAR") || t.contains("BINARY") || t.contains("DECIMAL");
    }

    private static String blankToDash(String s) {
        return (s == null || s.isBlank()) ? "—" : s.strip();
    }
}
```

### 4.5 `DbMcpServer` —— MCP Server 主体

> ★ 主入口。定义 4 个工具：list_tables / describe_table / run_query / explain_query。工具描述的措辞直接决定模型行为。
>
> **文件路径**：`src/main/java/com/example/mcp/db/DbMcpServer.java`

```java
package com.example.mcp.db;

import com.example.mcp.core.StdioLifecycle;

import io.modelcontextprotocol.json.McpJsonMapper;
import io.modelcontextprotocol.json.jackson3.JacksonMcpJsonMapperSupplier;
import io.modelcontextprotocol.server.McpServer;
import io.modelcontextprotocol.server.McpSyncServer;
import io.modelcontextprotocol.spec.McpSchema;

import java.sql.Connection;
import java.sql.ResultSet;
import java.sql.ResultSetMetaData;
import java.sql.SQLException;
import java.sql.Statement;
import java.util.List;
import java.util.Map;

/**
 * 【工具层】只读数据库查询 MCP Server。
 *
 * 暴露 4 个工具：
 *   list_tables      —— 有哪些表
 *   describe_table   —— 某张表什么结构
 *   run_query        —— 执行只读 SELECT
 *   explain_query    —— 看执行计划，避免写出全表扫
 *
 * 分层结构（改动只影响最下面一层）：
 *
 *   ┌──────────────────────────────────────┐
 *   │ 本类：MCP 工具定义与 handler            │  ← 跟具体是什么库无关
 *   ├──────────────────────────────────────┤
 *   │ SqlGuard / AuditLog：安全层            │  ← 跟具体是什么库无关
 *   ├──────────────────────────────────────┤
 *   │ Db：数据源                             │  ← ★只有这层要换成你的库
 *   └──────────────────────────────────────┘
 */
public final class DbMcpServer {

    private static final int QUERY_TIMEOUT_SECONDS = 10;

    public static void main(String[] args) {
        // 演示模式：建库 + 灌测试数据 + 创建只读账号。
        // 设了 DB_URL 环境变量就自动跳过，改为校验外部测试库连通性。
        Db.init();
        System.err.println("[spare-db] 数据源: " + Db.describeTarget());

        McpJsonMapper jsonMapper = new JacksonMcpJsonMapperSupplier().get();

        // ================================================================
        // 工具 1：list_tables
        // ================================================================
        McpSchema.Tool listTablesTool = McpSchema.Tool.builder("list_tables",
                        Map.of("type", "object", "properties", Map.of()))
                .description("列出数据库中所有的表，包含表名、行数和中文说明。"
                        + "在写任何查询之前，如果不确定有哪些表可用，先调用这个工具。")
                .build();

        // ================================================================
        // 工具 2：describe_table
        //
        // 这是 4 个工具里最重要的一个。
        // 模型 SQL 写得对不对，九成取决于它有没有看懂表结构。
        // ================================================================
        McpSchema.Tool describeTableTool = McpSchema.Tool.builder("describe_table",
                        Map.of(
                                "type", "object",
                                "properties", Map.of(
                                        "table_name", Map.of(
                                                "type", "string",
                                                "description", "表名，可先用 list_tables 查看有哪些表")),
                                "required", List.of("table_name")))
                .description("查看某张表的完整字段结构，包含字段名、类型、是否可空、主键标记和中文注释。"
                        + "写查询前如果不确定字段名或字段含义，必须先调用这个工具——"
                        + "不要凭猜测写字段名。")
                .build();

        // ================================================================
        // 工具 3：run_query
        // ================================================================
        McpSchema.Tool runQueryTool = McpSchema.Tool.builder("run_query",
                        Map.of(
                                "type", "object",
                                "properties", Map.of(
                                        "sql", Map.of(
                                                "type", "string",
                                                "description", "一条 SELECT 语句。不要带分号，不要写多条语句。")),
                                "required", List.of("sql")))
                .description("执行一条只读 SELECT 查询并返回结果表格。"
                        + "只允许 SELECT，任何写操作都会被拒绝。结果最多返回 "
                        + SqlGuard.MAX_ROWS + " 行，超出会截断。"
                        + "建议：先用 list_tables 和 describe_table 确认表结构，再写查询。")
                .build();

        // ================================================================
        // 工具 4：explain_query
        // ================================================================
        McpSchema.Tool explainQueryTool = McpSchema.Tool.builder("explain_query",
                        Map.of(
                                "type", "object",
                                "properties", Map.of(
                                        "sql", Map.of(
                                                "type", "string",
                                                "description", "要分析的 SELECT 语句。")),
                                "required", List.of("sql")))
                .description("查看一条查询的执行计划，用来判断它会不会全表扫描。"
                        + "当你不确定某个查询在大表上是否高效时使用。")
                .build();

        // ================================================================
        // 组装
        // ================================================================
        StdioLifecycle.Handle lifecycle = StdioLifecycle.create(jsonMapper);

        McpSyncServer server = McpServer.sync(lifecycle.provider())
                .serverInfo("spare-db", "1.0.0")
                .capabilities(McpSchema.ServerCapabilities.builder().tools(true).build())

                .toolCall(listTablesTool, (exchange, request) -> {
                    long t0 = System.nanoTime();
                    try (Connection conn = Db.readOnlyConnection()) {
                        String out = SchemaIntrospector.listTables(conn);
                        AuditLog.record("list_tables", "-", true, "ok", ms(t0));
                        return text(out);
                    } catch (SQLException e) {
                        AuditLog.record("list_tables", "-", false, e.getMessage(), ms(t0));
                        return error("查询表列表失败：" + e.getMessage());
                    }
                })

                .toolCall(describeTableTool, (exchange, request) -> {
                    long t0 = System.nanoTime();
                    String table = String.valueOf(request.arguments().get("table_name"));
                    try (Connection conn = Db.readOnlyConnection()) {
                        String out = SchemaIntrospector.describeTable(conn, table);
                        AuditLog.record("describe_table", table, true, "ok", ms(t0));
                        return text(out);
                    } catch (SQLException e) {
                        AuditLog.record("describe_table", table, false, e.getMessage(), ms(t0));
                        return error("查询表结构失败：" + e.getMessage());
                    }
                })

                .toolCall(runQueryTool, (exchange, request) -> {
                    String sql = String.valueOf(request.arguments().get("sql"));
                    long t0 = System.nanoTime();

                    // ---- 安全层：校验 ----
                    SqlGuard.Verdict verdict = SqlGuard.inspect(sql);
                    if (!verdict.ok()) {
                        // 被拒绝也记审计——被拒绝的请求比成功的更有信息量
                        AuditLog.record("run_query", sql, false, verdict.reason(), ms(t0));
                        // 用 isError 返回，模型看到具体原因才知道怎么改
                        return error("SQL 被拒绝：" + verdict.reason());
                    }

                    // ---- 执行 ----
                    try (Connection conn = Db.readOnlyConnection();
                         Statement st = conn.createStatement()) {
                        st.setQueryTimeout(QUERY_TIMEOUT_SECONDS);
                        try (ResultSet rs = st.executeQuery(verdict.sql())) {
                            String out = formatResultSet(rs);
                            AuditLog.record("run_query", sql, true, "ok", ms(t0));
                            return text(out);
                        }
                    } catch (SQLException e) {
                        AuditLog.record("run_query", sql, false, e.getMessage(), ms(t0));
                        // 把数据库的报错原样回给模型，它通常能自己改对
                        return error("SQL 执行失败：" + e.getMessage());
                    }
                })

                .toolCall(explainQueryTool, (exchange, request) -> {
                    String sql = String.valueOf(request.arguments().get("sql"));
                    long t0 = System.nanoTime();

                    SqlGuard.Verdict verdict = SqlGuard.inspect(sql);
                    if (!verdict.ok()) {
                        AuditLog.record("explain_query", sql, false, verdict.reason(), ms(t0));
                        return error("SQL 被拒绝：" + verdict.reason());
                    }

                    try (Connection conn = Db.readOnlyConnection();
                         Statement st = conn.createStatement()) {
                        st.setQueryTimeout(QUERY_TIMEOUT_SECONDS);
                        try (ResultSet rs = st.executeQuery("EXPLAIN " + verdict.sql())) {
                            String out = formatResultSet(rs);
                            AuditLog.record("explain_query", sql, true, "ok", ms(t0));
                            return text(out);
                        }
                    } catch (SQLException e) {
                        AuditLog.record("explain_query", sql, false, e.getMessage(), ms(t0));
                        return error("EXPLAIN 失败：" + e.getMessage());
                    }
                })

                .build();

        System.err.println("[spare-db] 已启动。审计日志: " + AuditLog.logFile());

        // 阻塞直到客户端断开（stdin EOF），然后干净退出。
        // 这样不会留下孤儿进程，退出码也是 0。
        lifecycle.awaitClientDisconnect();
        try {
            server.closeGracefully();
        } catch (Exception ignored) {
            // 已经关了，正常
        }
    }

    // ------------------------------------------------------------------
    // 结果格式化
    // ------------------------------------------------------------------

    /**
     * 把 ResultSet 渲染成 Markdown 表格。
     *
     * 为什么用 Markdown 而不是 JSON？
     * 因为模型读表格比读 JSON 更准，而且 token 更省（不用重复字段名）。
     */
    private static String formatResultSet(ResultSet rs) throws SQLException {
        ResultSetMetaData md = rs.getMetaData();
        int cols = md.getColumnCount();

        StringBuilder sb = new StringBuilder();

        sb.append("| ");
        for (int i = 1; i <= cols; i++) {
            sb.append(md.getColumnLabel(i)).append(" | ");
        }
        sb.append('\n').append('|');
        for (int i = 1; i <= cols; i++) {
            sb.append("---|");
        }
        sb.append('\n');

        int rows = 0;
        while (rs.next()) {
            sb.append("| ");
            for (int i = 1; i <= cols; i++) {
                sb.append(cell(rs.getObject(i))).append(" | ");
            }
            sb.append('\n');
            rows++;
        }

        sb.append("\n（").append(rows).append(" 行）");
        if (rows >= SqlGuard.MAX_ROWS) {
            sb.append(" ⚠️ 已达返回上限 ").append(SqlGuard.MAX_ROWS)
              .append(" 行，结果可能被截断。如需完整数据请加聚合条件或缩小范围。");
        }
        return sb.toString();
    }

    /** 单元格渲染：处理 null、换行、长文本、竖线转义。 */
    private static String cell(Object value) {
        if (value == null) {
            return "NULL";
        }
        String s = String.valueOf(value)
                .replace("|", "\\|")     // 不转义会撑坏 Markdown 表格
                .replaceAll("\\s+", " ") // 换行会把表格打散
                .strip();
        return s.length() > 200 ? s.substring(0, 200) + "…" : s;
    }

    private static McpSchema.CallToolResult text(String content) {
        return McpSchema.CallToolResult.builder()
                .addTextContent(content)
                .isError(false)
                .build();
    }

    private static McpSchema.CallToolResult error(String message) {
        return McpSchema.CallToolResult.builder()
                .addTextContent(message)
                .isError(true)
                .build();
    }

    private static long ms(long startNanos) {
        return (System.nanoTime() - startNanos) / 1_000_000;
    }
}
```

### 4.6 `DbAgentMain` —— 接 LLM 的入口

> 带 check / chat / 单次提问三种模式。
>
> **文件路径**：`src/main/java/com/example/mcp/db/DbAgentMain.java`

```java
package com.example.mcp.db;

import com.example.mcp.core.McpAgent;

import java.util.Arrays;
import java.util.Scanner;

/**
 * 把「只读数据库 MCP」接到 Claude 上——完整可用的自然语言查库。
 *
 * 自检（不需要 API Key，先确认 MCP 侧接好了）：
 *   mvn -q compile exec:exec -DmainClass=com.example.mcp.db.DbAgentMain -DappArgs=check
 *
 * 默认问题（需要 ANTHROPIC_API_KEY）：
 *   mvn -q compile exec:exec -DmainClass=com.example.mcp.db.DbAgentMain
 *
 * 自定义问题：
 *   mvn -q compile exec:exec -DmainClass=com.example.mcp.db.DbAgentMain \
 *       -DappArgs="9 月份领用数量最多的 5 个备件是什么"
 *
 * 交互模式（连接一次，连续提问）：
 *   mvn -q compile exec:exec -DmainClass=com.example.mcp.db.DbAgentMain -DappArgs=chat
 */
public final class DbAgentMain {

    /** 指向我们的数据库 MCP Server。换 server 只改这一行。 */
    private static final String SERVER = "com.example.mcp.db.DbMcpServer";

    private static final String DEFAULT_QUESTION =
            "9 月份领用数量最多的 5 个备件是什么？分别用在哪个部门？";

    public static void main(String[] args) {
        // pom 里的 ${appArgs} 为空时会传进来一个空字符串参数，先过滤掉，
        // 否则它会被当成"问题为空"而不是"没带参数"
        String[] effective = Arrays.stream(args)
                .filter(a -> !a.isBlank())
                .toArray(String[]::new);

        if (effective.length == 1 && effective[0].equals("check")) {
            dryRun();
            return;
        }

        if (effective.length == 1 && effective[0].equals("chat")) {
            runInteractive();
            return;
        }

        String question = effective.length > 0
                ? String.join(" ", effective)
                : DEFAULT_QUESTION;

        // try-with-resources 保证 MCP server 子进程被正确终止
        try (McpAgent agent = McpAgent.connect(SERVER)) {
            agent.ask(question);
        }
    }

    /**
     * 自检：只连 MCP，不调用模型。
     *
     * 建议第一次跑的时候先用这个。它能验证：
     *   - server 子进程能起来
     *   - 握手成功、工具清单能拿到
     *   - 工具 schema 能转成 Claude 格式而不报错
     *
     * 这些都不需要 API Key。确认没问题了再去跑真正的提问，
     * 免得把一个配置问题误判成"模型不好用"。
     */
    private static void dryRun() {
        System.out.println("目标数据源: " + Db.describeTarget());
        try (McpAgent agent = McpAgent.connect(SERVER)) {
            System.out.println();
            System.out.println("✅ 自检通过：MCP Server 连接正常，工具已全部加载。");
            System.out.println();
            System.out.println("下一步（需要 ANTHROPIC_API_KEY）：");
            System.out.println("  mvn -q exec:exec -DmainClass=" + DbAgentMain.class.getName());
            System.out.println("  mvn -q exec:exec -DmainClass=" + DbAgentMain.class.getName() + " -DappArgs=chat");
        }
    }

    /**
     * 交互模式。
     *
     * 注意这里只建立一次 MCP 连接，所有问题复用同一个 agent。
     * 现实中的对话产品都是这么做的——每次提问都重启一个 server 进程太浪费。
     *
     * 但要注意：ask() 每次都是从空的对话历史开始，
     * 所以它没有跨轮记忆。要做多轮对话，需要把 messages 提升为 agent 的字段。
     * （这是个很好的练习——自己动手改改看。）
     */
    private static void runInteractive() {
        try (McpAgent agent = McpAgent.connect(SERVER);
             Scanner scanner = new Scanner(System.in, "UTF-8")) {

            System.out.println();
            System.out.println("输入问题，回车执行。输入 exit 退出。");
            System.out.println();

            while (true) {
                System.out.print("> ");
                System.out.flush();

                if (!scanner.hasNextLine()) {
                    break;
                }
                String line = scanner.nextLine().strip();

                if (line.isEmpty()) {
                    continue;
                }
                if (line.equalsIgnoreCase("exit") || line.equalsIgnoreCase("quit")) {
                    break;
                }

                agent.ask(line);
                System.out.println();
            }
        }
    }
}
```

### 5.1 `DbClientDemo` —— 功能 + 安全验证

> 验证工具功能、7 个攻击用例、6 个误伤检查。不需要 API Key。
>
> **文件路径**：`src/main/java/com/example/mcp/db/DbClientDemo.java`

```java
package com.example.mcp.db;

import io.modelcontextprotocol.client.McpClient;
import io.modelcontextprotocol.client.McpSyncClient;
import io.modelcontextprotocol.client.transport.ServerParameters;
import io.modelcontextprotocol.client.transport.StdioClientTransport;
import io.modelcontextprotocol.json.McpJsonMapper;
import io.modelcontextprotocol.json.jackson3.JacksonMcpJsonMapperSupplier;
import io.modelcontextprotocol.spec.McpSchema;

import java.time.Duration;
import java.util.Map;

/**
 * 验证客户端：不接 LLM，直接把 4 个工具跑一遍。
 *
 * 分三部分：
 *   ① 正常功能   —— 证明工具能用
 *   ② 攻击用例   —— 证明安全层挡得住
 *   ③ 误伤检查   —— 证明安全层没有过度拦截
 *
 * 第 ③ 部分最容易被忽略，但同样重要：
 * 一个把正常查询也拦掉的安全层，等于没有。
 *
 * 运行：
 *   mvn -q compile exec:exec -DmainClass=com.example.mcp.db.DbClientDemo
 */
public final class DbClientDemo {

    public static void main(String[] args) {
        McpJsonMapper jsonMapper = new JacksonMcpJsonMapperSupplier().get();

        ServerParameters serverParams = ServerParameters.builder("java")
                .args("-Dfile.encoding=UTF-8",
                      "-Dstdout.encoding=UTF-8",
                      "-Dstderr.encoding=UTF-8",
                      "-classpath", System.getProperty("java.class.path"),
                      "com.example.mcp.db.DbMcpServer")
                .build();

        McpSyncClient client = McpClient.sync(new StdioClientTransport(serverParams, jsonMapper))
                .requestTimeout(Duration.ofSeconds(30))
                .build();

        try {
            client.initialize();

            section("① 正常功能");

            show("list_tables", call(client, "list_tables", Map.of()));
            show("describe_table(spare_usage)",
                    call(client, "describe_table", Map.of("table_name", "spare_usage")));

            // 这就是最终要交给模型的典型问题
            show("run_query —— 9 月领用最多的 5 个备件",
                    call(client, "run_query", Map.of("sql", """
                            SELECT p.code, p.name, SUM(u.quantity) AS total
                            FROM spare_usage u
                            JOIN spare_part p ON p.id = u.part_id
                            WHERE u.used_at >= DATE '2026-09-01' AND u.used_at < DATE '2026-10-01'
                            GROUP BY p.code, p.name
                            ORDER BY total DESC
                            LIMIT 5
                            """)));

            section("② 攻击用例 —— 应该全部被拒绝");

            attack(client, "删表", "DELETE FROM spare_part");
            attack(client, "改数据", "UPDATE spare_stock SET quantity = 0");
            attack(client, "堆叠语句", "SELECT * FROM spare_part; DROP TABLE spare_part");
            attack(client, "SELECT INTO 建表", "SELECT * INTO backup FROM spare_part");
            attack(client, "读服务器文件", "SELECT FILE_READ('/etc/passwd')");
            attack(client, "注释隐藏关键字", "SEL/**/ECT 1; DE/**/LETE FROM spare_part");
            attack(client, "行注释隐藏", "SELECT 1 -- \n; DROP TABLE spare_part");

            section("③ 误伤检查 —— 应该全部放行");

            pass(client, "字符串里的关键字不算数",
                    "SELECT * FROM spare_part WHERE name = 'delete me'");
            pass(client, "字段名含关键字子串",
                    "SELECT * FROM spare_part WHERE code LIKE 'UPDATED%'");
            // 这两条用 5000 行的 device_log，才能真实验证上限机制。
            // 用小表测等于没测——小表本来就查得完，看不出 LIMIT 有没有生效。
            pass(client, "没写 LIMIT（5000行表）",
                    "SELECT * FROM device_log");
            pass(client, "超大 LIMIT 应被收敛",
                    "SELECT * FROM device_log LIMIT 999999");
            pass(client, "聚合查询不受限（正确姿势）",
                    "SELECT level, COUNT(*) AS cnt FROM device_log GROUP BY level ORDER BY cnt DESC");
            pass(client, "CTE 查询",
                    "WITH recent AS (SELECT * FROM spare_usage WHERE used_at >= DATE '2026-09-01') "
                            + "SELECT part_id, SUM(quantity) FROM recent GROUP BY part_id");

            section("④ 最后一道墙 —— 数据库只读账号");

            System.out.println("上面 ② 测的是 SqlGuard（第二道墙）。");
            System.out.println("但它挡不住「绕过 Java 代码直接连库」的攻击，也挡不住 SqlGuard 自身被绕过。");
            System.out.println();
            System.out.println("最后一道墙是数据库权限本身，它需要单独验证：");
            System.out.println("    mvn -q compile exec:exec -DmainClass=com.example.mcp.db.ReadOnlyAccountDemo");
            System.out.println();
            System.out.println("（不能在这个类里测——H2 内存库是 per-JVM 的，");
            System.out.println("  这里的连接会开到本进程的空库，而不是 server 子进程里那个库。）");

        } finally {
            client.closeGracefully();
        }

        System.out.println();
        System.out.println("审计日志：" + AuditLog.logFile());
    }

    // ------------------------------------------------------------------

    private static void section(String title) {
        System.out.println();
        System.out.println("═".repeat(72));
        System.out.println("  " + title);
        System.out.println("═".repeat(72));
    }

    private static void show(String label, McpSchema.CallToolResult r) {
        System.out.println();
        System.out.println("── " + label + " ──");
        System.out.println(text(r));
    }

    private static void attack(McpSyncClient client, String label, String sql) {
        McpSchema.CallToolResult r = call(client, "run_query", Map.of("sql", sql));
        boolean blocked = Boolean.TRUE.equals(r.isError());
        System.out.printf("%-4s %-22s %s%n",
                blocked ? "✅" : "❌",
                label,
                blocked ? firstLine(text(r)) : "!!! 未被拦截： " + firstLine(text(r)));
    }

    private static void pass(McpSyncClient client, String label, String sql) {
        McpSchema.CallToolResult r = call(client, "run_query", Map.of("sql", sql));
        boolean ok = !Boolean.TRUE.equals(r.isError());
        System.out.printf("%-4s %-22s %s%n",
                ok ? "✅" : "❌",
                label,
                ok ? lastLine(text(r)) : "!!! 被误伤： " + firstLine(text(r)));
    }

    private static McpSchema.CallToolResult call(McpSyncClient client, String tool,
                                                 Map<String, Object> args) {
        return client.callTool(new McpSchema.CallToolRequest(tool, args));
    }

    private static String text(McpSchema.CallToolResult r) {
        StringBuilder sb = new StringBuilder();
        for (McpSchema.Content c : r.content()) {
            if (c instanceof McpSchema.TextContent t) {
                sb.append(t.text());
            }
        }
        return sb.toString();
    }

    private static String firstLine(String s) {
        for (String line : s.split("\n")) {
            if (!line.isBlank()) {
                return line.strip();
            }
        }
        return s.strip();
    }

    private static String lastLine(String s) {
        String[] lines = s.split("\n");
        for (int i = lines.length - 1; i >= 0; i--) {
            if (!lines[i].isBlank()) {
                return lines[i].strip();
            }
        }
        return s.strip();
    }
}
```

### 5.2 `ReadOnlyAccountDemo` —— 只读账号验证

> 绕过全部 Java 代码，直接用只读账号攻击数据库。这是唯一能证明第一道墙有效的方法。
>
> **文件路径**：`src/main/java/com/example/mcp/db/ReadOnlyAccountDemo.java`

```java
package com.example.mcp.db;

import java.sql.Connection;
import java.sql.SQLException;
import java.sql.Statement;

/**
 * 验证【第一道墙】：数据库只读账号。
 *
 * ══════════════════════════════════════════════════════════════════
 *  这个类为什么必须单独存在
 * ══════════════════════════════════════════════════════════════════
 *
 * 因为它演示的东西，是整个安全设计里唯一不可替代的一环。
 *
 * SqlGuard（第二道墙）能挡住模型"不小心"写出的危险 SQL，
 * 但它有两个绕不过去的问题：
 *
 *   1. 手写的 SQL 解析器不可能完备。SQL 方言、嵌套注释、
 *      数据库特有语法……总有绕过路径。
 *   2. 它拦不住"绕过 Java 代码"的攻击。谁能直连数据库，
 *      SqlGuard 就形同虚设。
 *
 * 而只读账号是**数据库自己 enforced** 的：
 * 不管你的代码写成什么样，不管谁在连，DELETE 就是执行不了。
 *
 * 这里刻意绕开全部业务代码，直接用只读账号连库执行写操作。
 * 全部被拒绝 = 这道墙有效。
 * ══════════════════════════════════════════════════════════════════
 *
 * 运行：
 *   mvn -q compile exec:exec -DmainClass=com.example.mcp.db.ReadOnlyAccountDemo
 */
public final class ReadOnlyAccountDemo {

    public static void main(String[] args) {
        // 在【本进程】里建库——H2 内存库是 per-JVM 的，
        // 所以必须自己 init 一份，不能用 server 子进程那个。
        Db.init();

        System.out.println("已用只读账号 app_readonly 建立连接，尝试执行写操作：");
        System.out.println("（这些操作全部绕过了 SqlGuard，直接打到数据库）");
        System.out.println();

        // 写操作 —— 应该全部被数据库拒绝
        expectDenied("DELETE FROM spare_part");
        expectDenied("DROP TABLE spare_part");
        expectDenied("TRUNCATE TABLE spare_usage");
        expectDenied("INSERT INTO spare_part (id, code, name) VALUES (999, 'X', 'X')");
        expectDenied("UPDATE spare_stock SET quantity = 0");

        System.out.println();
        System.out.println("对照组 —— 读操作应该正常：");
        System.out.println();

        // 读操作 —— 应该正常
        expectAllowed("SELECT COUNT(*) FROM spare_part");
        expectAllowed("SELECT COUNT(*) FROM spare_usage");

        System.out.println();
        System.out.println("结论：即使第二道墙（SqlGuard）被完全绕过，");
        System.out.println("      数据依然改不掉。这就是为什么只读账号不能省。");
    }

    private static void expectDenied(String sql) {
        try (Connection conn = Db.readOnlyConnection();
             Statement st = conn.createStatement()) {
            st.execute(sql);
            System.out.printf("%-4s %-52s → !!! 竟然成功了%n", "❌", sql);
        } catch (SQLException e) {
            System.out.printf("%-4s %-52s → %s%n", "✅", sql, brief(e));
        }
    }

    private static void expectAllowed(String sql) {
        try (Connection conn = Db.readOnlyConnection();
             Statement st = conn.createStatement();
             var rs = st.executeQuery(sql)) {
            rs.next();
            System.out.printf("%-4s %-52s → %s%n", "✅", sql, rs.getString(1) + " 行");
        } catch (SQLException e) {
            System.out.printf("%-4s %-52s → !!! 被误伤: %s%n", "❌", sql, brief(e));
        }
    }

    /** 数据库的错误信息很长，截到第一行就够说明问题了。 */
    private static String brief(SQLException e) {
        String msg = e.getMessage();
        if (msg == null) {
            return e.getClass().getSimpleName();
        }
        int nl = msg.indexOf('\n');
        return nl > 0 ? msg.substring(0, nl) : msg;
    }
}
```
